# Go API SOP

通用流程见 [Go 入口](../SKILL.md)，授权与敏感信息处理见 [安全](../../common/security/SKILL.md)，验证方法见 [测试](../../common/testing/SKILL.md)。

## 协议与请求链路
1. 阅读路由注册、拦截链、相邻 handler、DTO、service 和错误映射，沿用实际框架与协议。
2. 明确调用方、认证身份和资源权限；边界层解析与校验失败后立即返回，不继续昂贵 I/O。
3. DTO 注明用途、场景、字段来源、tag、必填性、空值、单位、枚举、默认值和前后端映射；变更联查客户端、handler、service、repository 及旧客户端行为。
4. handler 只处理接口边界，由 service 编排业务，保留事务、幂等和补偿顺序；数据访问与响应编码分离。
5. 保持 HTTP 状态、业务错误码、响应结构和 RPC 错误语义；内部诊断上下文不直接作为响应返回。
6. 数据库和外部调用沿用请求 context，分配超时并释放 cancel；独立任务有显式生命周期，不借脱离 context 掩盖超时。

## 幂等与容量
- 写接口的幂等键绑定调用主体和请求语义，明确存储、保留期、载荷冲突、并发处理和超时后的结果查询方式。
- 仅对可安全重放操作重试，限制次数、总预算并退避，避免放大下游压力。
- body、上传、分页、扇出和队列有上限及超限响应；容量目标依据请求率、并发、响应大小和下游预算。
- 限流明确用户、租户或 IP 等维度、拒绝及恢复行为，保证原子性并评估窗口边界突刺；高成本接口优先评估令牌桶、漏桶或滑动窗口。
- 流式读写处理取消、背压、大小限制及响应已开始后的失败语义。
- 异步接口区分任务受理与完成，提供可观测状态。
- 避免重复读取完整 body、重复鉴权和无必要的 panic 恢复层；存储与并发实现使用对应专题。

## 验证重点
- 协议快照、错误映射和旧客户端兼容；缺字段、未知枚举、空值、越权、超大 body 与分页上限。
- 重复提交、并发幂等冲突、下游超时、取消和部分失败。
- 代表性流量下的吞吐、P95/P99、错误率及连接池、队列压力；未压测不宣称容量已验证。
