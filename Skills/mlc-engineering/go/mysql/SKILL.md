# MySQL SOP

通用流程见 [Go 入口](../SKILL.md)，输入安全与验证分别见 [安全](../../common/security/SKILL.md)、[测试](../../common/testing/SKILL.md)。先确认版本、引擎、隔离级别和访问方式，以实际规模和分布评估风险。

## 查询与分页
1. 阅读表结构、索引、调用点、模型映射及事务封装，明确筛选、排序、空值、时区、精度、返回字段和一致性要求。
2. 值使用参数绑定，表名、列名及排序方向使用受控白名单，不能用参数占位符代替标识符。
3. 按谓词、关联和排序核查索引列顺序、选择性、隐式转换及回表成本；用执行计划验证扫描量与结果放大，未知生产索引不推定存在。
4. 列表有最大页大小及唯一稳定排序；复合游标包含排序键和唯一决胜键，续页条件匹配方向与空值语义。并发插入或排序字段更新下，稳定排序不等于快照一致性。
5. 浅分页可保留 offset；深分页量化扫描代价并评估游标或结果快照。不默认无限返回、无限 preload 或循环 N+1。
6. 遵循项目 SQL 集中位置，在常量旁说明用途及索引、分页、事务或降级前提；联查字段类型、外键、扫描顺序和 tag，ORM 限制字段选择。

## 写入与故障边界
- 新建表或新增、修改字段的 SQL 必须为每个字段提供中文 `COMMENT`，说明业务含义；金额及数量注明单位，状态注明枚举值，时间注明精度及已确认的时区约定，空值、默认值、业务标识及版本号注明关键语义。已有注释随字段语义同步维护，不以 SQL 行注释代替字段 `COMMENT`，不臆造未确认的业务规则。
- 补充字段注释时保留原字段类型、默认值、空值约束及索引；已应用的迁移不能仅靠修改原文件更新数据库，应按项目迁移流程新增增量迁移，执行前确认环境与授权。
- 数据库模型、查询常量、Repository 映射和迁移中的业务注释、错误描述及日志默认使用中文；结构体每个字段都要有中文注释，说明数据库列含义、单位、空值、默认值、枚举或索引约束。SQL 表名、列名、索引名和外部协议字段按真实契约保留英文。
- 数据访问日志必须使用中文说明查询、写入、事务、锁等待、分页或失败上下文，并通过结构化字段保留表名、SQL 标识、错误码和游标等技术信息；禁止记录完整 SQL 参数中的密码、Token、密钥和个人敏感数据，不能把数据库原始错误直接返回给客户端。
- 原子数据库操作置于短事务，固定加锁顺序、校验受影响行数；事务内不等待外部 HTTP、消息确认或长时间计算。
- 更新删除限制范围，禁止无保护大范围写；批处理明确批大小、提交边界、进度及恢复方式。
- 死锁或瞬态错误按完整事务和业务幂等重试，限制次数及总预算；提交超时不等于回滚，通过业务键查询或幂等重试确认。
- I/O 传递 context，设置超时和连接池上限，处理 rows 关闭、迭代错误及回滚清理。
- 写后沿用缓存失效或事件发布策略，明确跨系统一致性窗口。
- DDL 评估锁表、复制延迟、迁移兼容与回退条件；会实际执行查询的计划分析先确认安全范围，不直接用于生产高风险语句。

## 缺表与迁移排障
- 多个新接口同时返回数据库错误时，先从入口定位实际 SQL、所需表/列及对应迁移；用只读方式核对**服务实际连接的环境和数据库**、迁移版本与 dirty 状态，不能仅凭迁移文件存在就认为已建表。客户端只收到通用错误时，应核查服务端请求 ID 和安全的数据库诊断，不向客户端泄露原始 SQL 错误。
- 建表、改表先写入项目约定的增量 up/down 迁移，核对依赖顺序、字段注释、索引、回退影响及已应用版本；不要直接手工建表绕过迁移版本，也不要修改已应用迁移来修线上结构。执行 SQL 文件或迁移前须获得目标环境的明确授权，确认地址、待执行版本范围及变更影响；未知库、共享库和生产库暂停并询问。不得把仅需只读诊断的场景升级为自动迁移。
- 获准执行时使用项目迁移入口，只运行已审查的目标版本范围；注意 `up` 可能执行所有未应用版本，不运行附带启动依赖、初始化或清理的脚本代替迁移。执行后只读核对迁移版本、dirty 状态和目标表/列，按授权范围验证受影响接口；失败时保留现场，不盲目重跑或强制改版本，评估 DDL 部分成功的状态。
- MLC_GO 的本地 debug 可用 `go run ./cmd/hg_config_check --env=debug --check=migration-version` 只读检查；`go run ./cmd/hg_config_check --env=debug --migrations-dir ./migrations` 会执行**所有待应用迁移**，必须先核对连接目标、版本差和授权；pre/prod 不套用 debug 结果。
- 迁移成功但接口仍报数据库错误时，必须在同一数据库只读执行实际查询确认原因；特别检查跨表 ID 列的字符集/排序规则（MySQL `1267`）、字段映射及扫描错误。表定义省略 `COLLATE` 时不要假定与旧表一致；修 JOIN 时检查比较语义和被查找列的索引可用性，不以扩大表 DDL 或吞掉错误替代定位。需要重启已运行的服务才能验证 SQL 常量修改是否生效。

## 性能与验证
- 大表 Join 评估驱动表、索引顺序及结果放大，必要时比较反范式、预计算或分步查询；统计、计数、排行评估缓存、异步汇总或离线聚合。
- 高频写评估热点行/索引、唯一键冲突、重试放大及 binlog/复制压力，不为优化改变过滤、排序、事务或公共错误语义。
- 覆盖参数绑定、字段映射、分页边界、并发更新、死锁重试、取消、部分批次失败及提交未知。
- 用代表性数据比较扫描/返回行数、P95/P99、锁等待、连接池等待及复制压力，记录索引前提和迁移影响。
