# Go 开发 SOP

范围控制、分层与依赖取舍见 [工程实施](../../common/engineering-workflow/SKILL.md)；安全、审查与交付见 [Go 入口](../SKILL.md)，验证见 [测试](../../common/testing/SKILL.md)。

## 调用链与契约
1. 核对模块规范、Go 构建配置、接口实现、调用方及相邻测试，区分流程编排、业务计算和外部 I/O。
2. 检查导出符号、输入输出、错误和业务顺序的兼容性；数据库模型、业务模型、API 模型分开，不为省代码随意合并。
3. 字段与 json、yaml、form、mapstructure、gorm、db、bson、xml 等 tag 变更联查调用方、数据库、缓存和迁移。
4. 依赖通过构造或参数传入，接口保持小而明确；只在职责或复用需要时拆函数、包或接口。

## 注释、日志与结构体
- 业务代码中的注释、打印内容、日志消息、错误描述和测试说明默认使用中文；变量名、参数名、函数名、类型名、包名、接口名及第三方协议字段按既有 Go/API 约定保留英文，不为中文化强行修改标识符或外部契约。
- 注释必须说明职责、业务背景、输入输出、单位、状态枚举、时区、并发/事务边界、失败条件或恢复方式等关键约束；禁止只重复代码字面含义的无效注释。复杂流程应在入口或关键分支前补充足够上下文，使未熟悉模块的维护者能够理解为什么这样处理。
- 所有新增或修改的结构体（包括未导出结构体）的每个成员字段都必须有中文注释，说明字段含义，并按实际情况补充来源、单位、是否可空、默认值、枚举值、序列化用途或一致性约束；数据库模型、业务模型、DTO、事件模型和响应模型均适用。字段已有 `json`、`db` 等 tag 不能替代字段注释。
- 日志必须使用中文描述业务事件和失败原因，保留必要的英文技术标识、错误码、路径、topic、表名或字段名作为结构化上下文；禁止输出密码、Token、密钥、完整连接串和不必要的个人隐私。日志级别应与事件严重性匹配，不能用打印替代项目日志设施。
- 新增或修改代码时同步检查相邻注释、日志和错误文本，发现明显英文业务描述应在本次触及范围内改为中文；第三方库、协议规范、SQL、HTTP 方法及标准错误语义可保留原文。
- 中文化不得破坏日志采集规则、告警匹配、结构化字段名、错误链或客户端依赖的错误协议；存在既有依赖时先确认兼容方案，第三方原始错误保留为诊断上下文，新增说明使用中文。不为落实本规范批量改写无关代码。

## 错误与资源
- 显式处理 error，用操作上下文包装并保留错误链，以 `errors.Is` / `errors.As` 识别；不用 panic 代替普通业务错误，不吞错。
- 沿调用链传递 context，为外部 I/O 分配预算并释放 cancel；请求链路不以 `context.Background()` 或 `context.TODO()` 替换上游 context。
- 明确响应体、结果集等资源的所有权、关闭时机及必要的收尾错误处理。
- 输入、结果集、批次、重试和异步任务有容量上限；后台任务有生命周期、退出等待及 panic 边界，细节见 [并发](../concurrency/SKILL.md)。
- 公开入口注释说明职责、单位、所有权或失败条件；协议结构体注明协议名称、用途和约束，修正失真注释；运维脚本说明前置条件、副作用与恢复办法。

## 性能方法
- 先记录负载、数据规模、延迟分位数、吞吐和资源基线，按实测瓶颈消除重复计算、循环 I/O 和无效分配。
- 避免重复鉴权、恢复层、body 读取及签名/哈希/序列化；拦截链尽量在启动期装配，热点请求减少拼接和分配。
- 先保证超时、取消、限流、熔断、降级、幂等与削峰，再优化缓存、批次和连接池；异步化不能破坏持久化确认和错误语义。
- 高成本接口评估对象存储直传、后台任务及有界队列；高频读评估缓存、请求合并和预计算，高频写评估分片、批量和幂等。
- 容量推演覆盖突刺、热点、重复提交、超时取消、资源放大、队列堆积及 DB/Redis/MQ 压力，不把压力无保护地传导到数据库。

## 验证重点
- 检查 nil、空集合、零值、溢出、超时、部分成功，以及接口、tag、错误链和资源所有权。
- 清理未使用 import、变量；沿用 goimports，否则 gofmt，仅格式化本次文件；按项目配置选择 go vet、相关 go test，并发变更评估 `-race`。
- 性能结论附可复现负载与前后指标，未压测不宣称支持特定并发量。
