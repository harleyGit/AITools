# React 实施流程

## 适用与协作
- 先读取目标项目 `AGENTS.md`，版本、目录、命名、组件形态及 UI 库禁令以其为准。
- 通用方法按需引用 `common/` 下的 `engineering-workflow`、`security`、`testing`、`code-review`；输出与提交参照 `dev_general_skill`。

## 1. 核查既有模式
- 阅读页面入口、组件树、状态来源、请求封装、样式及测试；确认 React 版本、构建脚本、类型体系和 React Compiler 配置。
- 沿用组件形态和当前版本支持的 API，不为追新迁移框架或组件库；类组件需要 Hook 路由能力时使用已有适配器，不绕过 Hook 调用规则。

## 2. 保持状态与契约清晰
- 明确状态所有者和数据单向流动，避免重复存储可直接推导的数据。
- 保持 props、交互及页面、VM、请求层边界；仅按职责或复用需要拆分组件，类组件复杂 JSX 可拆为 `renderXxx()`。
- 列表使用稳定业务标识作为 key，核对重排和局部状态是否保持正确。
- 状态更新保持不可变，依赖旧值时使用函数式更新；类组件不要直接修改 `this.state` 或假设 `setState` 后立即可读，并核对事件回调的 `this` 绑定。

## 3. 管理副作用与异步
- 将用户事件处理与外部系统同步分开，不为纯计算添加 Effect。
- 使用 Hook 时遵守调用规则，核对依赖、闭包读取和清理函数。
- 类组件核对生命周期配对；`componentDidUpdate` 仅在相关 props/state 变化时同步，避免无条件 `setState` 循环。
- 请求、订阅和计时器在卸载或依赖变化时清理，处理取消、竞态及过期结果覆盖。
- 检查重复挂载或重复触发下的行为，不以禁用开发检查掩盖副作用缺陷。
- 签名、鉴权和错误处理沿用请求层，不在组件内另造协议。

## 4. 按证据优化
- 先确认慢路径与渲染成本，再决定是否调整状态位置、拆分组件或引入缓存。
- 不默认添加 `useMemo` 或 `useCallback`，遵循项目编译器和性能策略。
- 仅在版本支持且能解决具体交互问题时考虑并发更新或延迟值等 API。
- 优化后检查依赖和状态一致性，避免为减少渲染引入陈旧数据。

## 5. 验证用户行为
- 覆盖加载、空态、错误、成功及重复提交路径，保留可理解的失败反馈。
- 检查桌面和移动端布局、键盘可操作性、焦点及控件语义。
- 检查受控输入、路由切换和异步返回后的状态保持与重置行为。
- 按项目脚本和 `testing` 选择验证；区分 Node 纯函数测试与需要 JSX 转换、DOM 环境或 Jest/Vitest 的测试，不猜测统一 `npm test` 入口。
