# Go 并发 SOP

通用流程与兼容边界见 [Go 入口](../SKILL.md)，验证方法见 [测试](../../common/testing/SKILL.md)。先确认 Go 版本、现有调度方式和运行环境。

## 调度与退出
1. 画出生产、排队、执行、汇总和退出链路，标注共享数据、所有权、输出顺序及原子状态变化。
2. 根据实际负载、CPU、连接池、请求预算及下游配额确定并发上限；使用现有工作池、信号量或固定 worker，在启动前限制准入，不先创建无限 goroutine 再等待。
3. 队列有容量及满载策略，明确阻塞、拒绝、丢弃或持久化条件；结果汇总也限制内存。
4. 每个 goroutine 有启动者、退出条件和等待或监督机制；保留上游 context，阻塞发送、接收、select 和 I/O 可取消、超时或退出。
5. 明确首错取消或部分成功语义，保留错误链、任务标识，设计正常/故障停止顺序并清理已启动任务。
6. panic 恢复遵循服务故障策略，不能把任务失败伪装为成功；重试有次数、退避、总时限且共用并发预算。

## 同步与所有权
- 按所有权选择 channel 或锁；无缓冲 channel 用于同步交接，缓冲 channel 只在明确容量下吸收突刺。
- channel 由唯一关闭方负责，通常由发送侧协调者等待全部发送结束后关闭；不向已关闭 channel 发送，接收端处理关闭状态，能限定方向时使用单向 channel。
- WaitGroup 在任务启动前登记计数，所有退出分支完成扣减；不用 `time.Sleep` 猜测完成。
- 锁保护完整不变量，固定多锁获取顺序、缩短持锁时间，不持锁执行不可控外部 I/O。
- map、slice 和复用缓冲区的共享修改须同步；原子变量不自动保证跨字段一致性，限流、幂等、锁和计数的复合变化须原子完成。
- 调度与业务计算分开，select 分支保持简单分发，避免忙等和阻塞发送泄漏。

## 验证重点
- 零任务、首任务失败、消费者提前退出、队列满、关闭竞态；取消后 goroutine、并发计数、队列及连接池占用应收敛。
- 相关 `go test -race` 只覆盖实际执行路径，不能证明无竞态。
- 压力测试比较 P95/P99、吞吐、阻塞、锁竞争和内存，不只看平均耗时；记录并发参数依据及关闭行为。
