# 代码审查流程

## 确定范围
- 确认分支、提交或工作区差异及基线，阅读项目规则、需求和测试，不默认只审最近一次提交。
- 区分新增与既有问题，不把风格偏好列为缺陷；默认只审查，修改须有授权。

## 追踪风险
- 沿调用链检查接口、数据格式、错误语义、持久化及外部副作用兼容性。
- 核对空值、边界、重复操作、失败恢复、取消、竞态、线程归属和资源生命周期。
- UI 关注加载、空态、错误态、键盘和屏幕适配；权限与数据风险按需使用 `security`。
- 只指出有实际影响的设计问题，不要求无依据的技术迁移；性能问题需有规模、热路径或测量证据。
- 检查关键新行为的断言是否有效，识别吞错、复制实现及不稳定依赖；需运行验证时遵循 `testing`。

## 复核与结论
- 每项确认触发条件、执行路径及影响，排除上游校验或其他分支已处理的情况；同根因合并。
- 发现优先，按严重性排序，给出文件/行号、错误行为及最小修复方向。
- 无法复现时标明证据限制，不把猜测或缺测试描述成已发生故障。
- 开放问题、验证缺口和简要总结放在发现之后；无发现时明确说明，保留实际验证限制。
