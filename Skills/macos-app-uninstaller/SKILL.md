# macOS 软件卸载与清理

## 执行方式

用户明确要求卸载软件时，运行：

```bash
scripts/uninstall_macos_app.sh "<软件名或.app路径>"
```

用户只要求查看残留或预览时，运行：

```bash
scripts/uninstall_macos_app.sh --dry-run "<软件名或.app路径>"
```

未提供名称时可交互输入：

```bash
scripts/uninstall_macos_app.sh
```

## 规则

1. 必须从实际 `.app/Contents/Info.plist` 读取 Bundle ID，不能猜测。
2. 按应用路径、主 Bundle ID、同命名空间的子 Bundle ID 和应用完整名称建立删除清单；禁止用宽泛关键词递归删除。
3. 默认输入软件名后自动执行；`--dry-run` 只预览。
4. 找到多个候选应用时要求用户选择，不能自行删除多个应用。
5. 系统级文件使用 macOS 原生管理员授权弹窗，不读取或保存密码。
6. 卸载后用只读扫描或文件检查复查并报告实际删除和残留；不要声称脚本已经自动复查。
7. 脚本不会清理用户自行创建的普通文档，也不会执行软件自带但内容未知的卸载脚本。
8. 名称相同但路径和 Bundle ID 无关的文件必须保留，例如其他软件组件中恰好包含同名关键词的文件。
9. 用户主目录中的同名可见目录默认视为用户数据，不自动删除；只有检查后能确认是应用生成且用户明确要求完整清理时才可删除。

## 磁盘清理（不同于卸载应用）

用户要求扫描或清理磁盘空间时，先只读运行：

```bash
./scripts/scan_app_junk.sh
```

无 `--days` 时扫描全部时间；用户提供时长时使用 `--days 30` 等，仅报告该天数以上未更新的候选。脚本只扫描当前用户标准目录与应用清单；不读取用户文稿内容，不扫描其他账户或整个系统卷。先向用户报告分类、数量和大小。用户明确要求清理时才运行（交互终端输入 `DELETE`）：

```bash
./scripts/scan_app_junk.sh --execute --days 30
```

`--execute` 没有 `--days` 时会清理**全部普通候选缓存和日志**，包括现用应用的可重建缓存；一定要先看清单。大于等于 256 MB 的缓存、CocoaPods/Yarn/Homebrew 等构建依赖缓存、应用迁移缓存及系统服务缓存会被列为“重要或大体积缓存/诊断”，**不自动删除**。无交互终端时只能对普通缓存/日志显式使用 `--yes`。重要缓存、下载目录安装包、疑似卸载应用数据仅提示，不得批量删除；需人工核实并逐项使用 `--select '路径' --include-review`、`--include-downloads` 或 `--include-data`，在交互终端输入 `DELETE`，不支持 `--yes`。任何声称“卸载残留”的数据只是候选，必须结合实际 App 安装位置/用途核实；同名普通文档、工作目录和其他应用文件不能删除。报告“已删除”清单及脚本给出的 MB/GB 估算，同时解释实际磁盘可用空间可能不同；对保留项逐一说明风险并给路径和单项命令。不要把测试目录执行结果说成真实 Mac 已清理。

## CocoaPods 按版本清理（专用脚本）

用户要求对 `~/Library/Caches/CocoaPods` 按版本裁剪时，不要用通用扫描器的 `--include-review` 整目录清除；必须先运行：

```bash
./scripts/prune_cocoapods_cache.sh
```

确认预览规则后，再运行：

```bash
./scripts/prune_cocoapods_cache.sh --execute
```

自动化非交互运行必须是在已核对预览、且用户明确要求执行时使用 `--execute --yes`。默认最近 15 天内有改动的条目全部保留，对每个 Pod 的 Release 和 External 分组分别至少保留最近 3 项（`--keep 2` 可改为 2 项）；最近 15 天超过 3 项的也全部保留。Release 是版本缓存，External 是哈希快照，不能声称哈希等同版本。只删除旧目录与精确同名的 Specs 条目，保留其余缓存结构。每次预览和执行都会自动在 `~/Desktop` 创建逐项日志，报告路径、计划/实际删除数量、估算和磁盘可用空间变化。失败项目须如实报告；清理后可能需要重新下载依赖，离线构建风险仍存在。
